## 快速上手（新机器 / 新人，3 条命令）

```bash
git clone <本仓库地址>
cd Isaac-RL-Two-wheel-Legged-Bot

./scripts/download_assets.sh   # ① 从上游 jaykorea 仓库获取机器人 USD 资产（git-lfs + 解压 zip）
./scripts/setup_env.sh         # ② 一键创建 Python 环境（~20GB：torch cu128 + Isaac Sim 4.5 + IsaacLab，耐心等）
./scripts/run_train.sh         # ③ 开始训练（默认 1024 envs, headless）
```

- 资产是开源发布的、不随本仓库提交（体积大）；`scripts/download_assets.sh` 会自动从上游拉取。
- `scripts/setup_env.sh` 会自动安装 IsaacLab（固定 commit）和 lab.flamingo（editable），无需手动 clone；
- 中途失败可重复执行（幂等）；环境损坏用 `FRESH=1 ./scripts/setup_env.sh` 全新重建。

## 0. 这个项目是什么

- **机器人**：Flamingo 双轮腿机器人（两轮 + 两条腿，髋/肩关节位置控制，轮子速度控制，共 8 个执行器）。
- **仿真训练**：Isaac Sim 4.5（物理引擎 PhysX，GPU 加速）+ Isaac Lab 2.3（RL 环境框架）。
- **算法**：PPO（仓库自带的 CO-RL 实现，基于 rsl_rl 风格，也支持 SRMPPO、off-policy 算法）。
- **部署**：训练好的策略导出为 ONNX，在真机嵌入式端用 ONNX Runtime 推理（50Hz 控制环）。
- **技术栈速查**：Python 3.10（venv：`~/wheel_legged/env_isaaclab`）、torch 2.7+cu128、gymnasium、hydra。

任务名（训练）：`Isaac-Velocity-Flat-Flamingo-v1-ppo`；播放：`Isaac-Velocity-Flat-Flamingo-Play-v1-ppo`。
环境结构：64/1024 个并行仿真环境，每个环境一个机器人；控制频率 50Hz（物理 200Hz = dt 0.005 × decimation 4）。

## 1. 完整工作流总览

```
┌────────────┐   ┌──────────────┐   ┌──────────────┐   ┌───────────────┐
│ 训练 train │──▶│ 评估 play    │──▶│ 导出 ONNX    │──▶│ 真机部署      │
│ run_train  │   │ run_play     │   │ (play 自动)  │   │ ONNX Runtime  │
└────────────┘   └──────────────┘   └──────────────┘   └───────────────┘
      │                 │                  │                   │
      ▼                 ▼                  ▼                   ▼
  checkpoint       检查点→导出        exported/           真机观测向量必须
  model_*.pt       policy.onnx       policy.onnx          与训练完全一致
```

**每一步的产出：**

| 步骤 | 命令 | 产出位置 |
|---|---|---|
| 训练 | `./scripts/run_train.sh` | `logs/co_rl/Flamingo_Flat_Stand_Drive/ppo/<时间戳>/`（checkpoint `model_*.pt` 每 100 迭代存一次，另有 `params/` 配置快照） |
| 评估/导出 | `./scripts/run_play.sh --load_run <时间戳>` | 同目录下 `exported/policy.onnx`、`policy.pt`、`env.pdf` |
| 可视化 | `HEADLESS=0 ./scripts/run_train.sh` 或 `--video` | 窗口实时画面 / `videos/train/*.mp4` |

> 所有脚本都在仓库根目录，**从仓库根目录执行**（脚本已自动设置好 PYTHONPATH 和 venv，不要直接抄 README 里的裸命令）。

## 2. 训练（train）

```bash
cd /home/glennade/wheel_legged/Isaac-RL-Two-wheel-Legged-Bot

# 正式训练（默认 1024 个并行环境，headless，无窗口）
./scripts/run_train.sh

# 常用变体
NUM_ENVS=512 ./scripts/run_train.sh                    # 更省内存（本机 15GB 内存/8GB 显存，别超过 1024）
./scripts/run_train.sh --max_iterations 500            # 只跑 500 轮迭代（默认 5000，笔记本上要跑很久）
./scripts/run_train.sh --resume True --load_run <时间戳> --checkpoint model_500.pt   # 断点续训
```

**参数含义（新人必懂）：**

| 参数 | 含义 | 建议 |
|---|---|---|
| `--num_envs` / `NUM_ENVS` | 并行仿真环境数。越多探索越多样、越快，但吃内存/显存 | 本机 512~1024 |
| `--max_iterations` | PPO 更新轮数上限 | 先用 500 试跑看效果 |
| `--headless` | 不开窗口 | 训练一律 headless |
| `--num_policy_stacks 2` | 策略观测堆叠 2 帧历史（时序信息） | 仓库默认 2，别乱改 |
| `--algo ppo` | 算法 | 另有 `srmppo` |

**训练时看什么（另开终端）：**
```bash
tail -f logs/train_*.log              # 训练日志（实时）
nvidia-smi                            # 显存/GPU 占用
free -h                               # 内存；swap 涨得猛就降 NUM_ENVS
env_isaaclab/bin/tensorboard --logdir logs/co_rl   # 曲线，浏览器开 http://localhost:6006
```

**训练日志里每行迭代的含义**：`Computation: 3000 steps/s`（每秒采样步数，衡量速度）、
`Mean reward`（平均奖励，训练初期为负且 `base_contact` 终止率高是正常的，机器人还没学会站稳）、
`Total timesteps`（累计步数 = 迭代数 × 24 × num_envs）。

## 4. 评估与导出 ONNX（play）

```bash
./scripts/run_play.sh --load_run 2026-08-18_20-26-20
```
- `--load_run` 填 `logs/co_rl/Flamingo_Flat_Stand_Drive/ppo/` 下的时间戳文件夹名；
- play 会加载 checkpoint 跑评估，并**自动导出** `exported/policy.onnx`（JIT 版 `policy.pt` 一起导出，另有 `env.pdf` 环境配置说明）；
- `--plot True` 输出运动数据曲线；`HEADLESS=0` 开窗看。

## 5. 部署到真机（sim2real）

策略本体不是难点（真机端跑 ONNX Runtime，50Hz 推理循环即可），**难点在接口对齐**。部署前必须保证：

1. **观测向量**：真机按训练时完全相同的顺序/单位构造观测（关节角/角速度、轮速、IMU 角速度、投影重力、速度指令、接触检测），并实现相同的 stacking 历史缓冲；
2. **状态估计**：`base_projected_gravity`（IMU）、`base_lin_vel`（轮式里程计）、`is_contact`（编码器/电流判断）都要自己实现；
3. **动作映射**：8 维输出按训练限位映射到髋/肩位置指令 + 轮速指令；
4. **频率**：严格 50Hz 控制环；
5. **归一化**：本仓库 `empirical_normalization=False`，ONNX 是 Identity 归一化——**真机喂原始观测即可，不要再归一化**。

仓库里的 `scripts/co_rl/play_dep.py` 即部署相关脚本；sim2sim（Lab→MuJoCo）在 `sim2sim_onnx` 分支。

## 6. 换你自己的双轮腿机器人（checklist）

"只换模型重训"不够，以下四块都要动：

- [ ] **① 机器人资产**：你的 URDF/MJCF → USD，保证关节定义、碰撞体、**质量/惯量/质心**准确（惯量不准 → sim2real 失败）；
- [ ] **② 任务配置**（`lab/flamingo/tasks/manager_based/locomotion/velocity/`）：
  - `velocity_env_cfg.py`：关节名（仓库写死 `.*_hip_joint` 等）、执行器类型/刚度/阻尼/力限、场景参数；
  - `flat_env/*_cfg.py`：观测项与 stacking、动作限位、奖励权重、终止条件；
- [ ] **③ 观测/动作**：维度随你的机器人自动变化，但**顺序和真机传感器必须一一对应**；
- [ ] **④ 奖励调参**：19 个奖励项的权重几乎都要按新机器人重调——这是"重新训练"里最花时间的部分。

PPO 超参（lr 1e-3、隐层 512/256/128）可先沿用仓库默认。

## 7. 常见问题速查

| 现象 | 处理 |
|---|---|
| 启动很久没输出 | 首次编译 shader/PSO，看日志是否在涨（见第 3 节） |
| `ImportError: dump_pickle` | 已修复（IsaacLab 2.3 兼容），勿回退 |
| GPU/CUDA 相关报错 | 先跑 `./scripts/diagnose_gpu.sh` |
| OOM / swap 涨 | `NUM_ENVS` 降到 512 |
| 训练初期一直摔倒 | 正常，PPO 要几万步才会站稳 |
| 环境坏了（torch/editable 消失） | **不要**对现有 venv 跑 `uv pip sync -r requirements.txt`（会拆环境）。重建：`FRESH=1 ./scripts/setup_env.sh` |

详细排障见《部署与卡死排查.md》。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| env | 一个并行仿真环境（一个机器人副本） |
| num_envs | 并行环境数，越大样本效率越高、越吃资源 |
| iteration / max_iterations | PPO 更新一轮 = 采集 num_envs×24 步 + 学习一次 |
| steps/s | 每秒采集的仿真步数，衡量训练速度 |
| decimation | 物理步与控制步之比（4 = 每个控制步跑 4 次物理，50Hz 控制） |
| stacking | 观测拼接前几帧，给策略时序信息（本仓库 2 帧） |
| headless | 无窗口模式，省内存，训练用 |
| checkpoint | 训练中途保存的模型权重（model_XXX.pt） |
| sim2real | 仿真训练 → 真机部署的迁移过程 |
| ONNX | 跨平台模型格式，真机端用 ONNX Runtime 加载推理 |
