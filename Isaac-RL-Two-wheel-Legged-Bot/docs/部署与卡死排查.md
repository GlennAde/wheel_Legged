## 3. GPU 不通怎么办（第 1/2/3 项 FAIL 时）

### 症状
- `nvidia-smi` 报 `couldn't communicate with the NVIDIA driver`
- 或 `/dev/nvidiactl /dev/nvidia0 /dev/nvidia-uvm` 不存在
- 表现到 Isaac Sim 上：启动时**卡死/无响应**（Kit 反复尝试初始化 CUDA/PhysX），
  或直接报 `CUDA initialization failure`。

### 原因
驱动模块加载了，但设备节点没建出来 —— 最常见于**驱动升级后没有重启**，
或 udev 规则没触发。这台机器 `nvidia_uvm` 模块引用计数为 0，说明自开机以来
**没有任何 CUDA 程序成功跑过**，和“从没启动成功过”完全吻合。

### 修复（需要 sudo，按顺序试）

**方案 A：重启（最省事、最可靠）**
```bash
sudo reboot
```
重启后立刻 `nvidia-smi` 验证。

**方案 B：不重启，重载驱动模块（让驱动重新创建设备节点）**
```bash
sudo modprobe -r nvidia_drm nvidia_modeset nvidia_uvm nvidia
sudo modprobe nvidia nvidia_uvm nvidia_modeset nvidia_drm
ls -l /dev/nvidia*
```
（注意：如果正在用 X 图形界面，卸载 nvidia_drm 可能黑屏，先关掉所有 GUI 程序，
或直接用方案 A。）

**方案 C：手动创建设备节点（B 无效时）**
```bash
sudo mknod -m 666 /dev/nvidiactl c 195 255
sudo mknod -m 666 /dev/nvidia0    c 195 0
sudo mknod -m 666 /dev/nvidia-uvm c 509 0
sudo chmod 666 /dev/nvidia*
```

**方案 D：重装驱动（A/B/C 都不行时）**
```bash
sudo apt install --reinstall nvidia-dkms-580 nvidia-utils-580 nvidia-kernel-common-580
sudo reboot
```

修复后**再跑一遍 `./diagnose_gpu.sh`**，直到 1/2/3 全部 PASS。

## 5. 卡死的真正原因与对策（这台机器的关键）

### 5.1 内存只有 15GB —— 这是头号杀手
Isaac Sim 4.5 本身就要 **8~12GB 内存**；仓库默认 `--num_envs 4096` 训练
要 **20GB+**。内存不够时系统直接冻结（OOM），这就是你之前卡死、加 swap 的原因。

对策（按重要性）：
1. **永远用 `--headless`** 训练（省掉 GUI 的几 GB）。
2. **num_envs 降到 512~1024**（8GB 显存 + 15GB 内存的合理区间）：
   ```bash
   NUM_ENVS=1024 ./run_train.sh        # 常规
   NUM_ENVS=512  ./run_train.sh        # 更保守
   ```
3. **调低 swap 倾向**（你有 47GB swap，但默认 swappiness=60 会让系统频繁换页 → 卡顿假死）：
   ```bash
   sudo sysctl vm.swappiness=10
   # 永久生效：echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
   ```

### 5.2 显存只有 8GB
- 4096 envs 会爆显存（CUDA OOM），512~1024 envs 才安全。
- 训练时**不要**加 `--video` / `--enable_cameras`（要渲染相机，显存不够）。

### 5.3 磁盘
- 根分区 `/` 已用 81%（剩约 14G）。Isaac Sim 的缓存/日志在 `/home`（sda3，剩 265G），
  一般没问题；但别把训练日志写到 `/` 下。
- 可选清理：`rm -rf ~/.cache/pip`（有 6.6GB，装完包就没用了）。

### 5.4 笔记本混合显卡（Intel + NVIDIA）
- 带 GUI 启动时 OpenGL 可能被 Intel 核显接管 → 花屏/黑屏/卡死。
- **训练一律 `--headless`**；要看画面，用 `--headless --video` 录视频，
  或播放时 `./run_play.sh --load_run <run> --plot True`（仍建议 headless）。

### 5.5 关于你已经扩的 swap
- 47GB swap 是对的，能防止 OOM 硬冻结；但 swap 救不了显存，也救不了
  “GPU 设备节点缺失”。先把第 3 节 GPU 修好，再谈参数。

## 7. 常见报错速查

| 报错 | 含义 / 处理 |
|---|---|
| `ImportError: cannot import name 'dump_pickle' from 'isaaclab.utils.io'` | 仓库按 IsaacLab 2.0 写的，装的是 2.3（已删 dump_pickle）。**已修复**：train.py 内置了本地 dump_pickle 替代 |
| `ModuleNotFoundError: isaaclab_tasks.utils.wrappers.co_rl` | 只出现在类型注解里（不执行）。**已修复**：cli_args.py 改为引用仓库自带 CoRlPolicyRunnerCfg |
| `couldn't communicate with the NVIDIA driver` | 驱动设备节点问题 → 第 3 节 |
| **环境损坏**：torch 报 `libcusparseLt.so.0` / `torchgen` 缺失、editable 包消失、`pip check` 大量断裂 | 对现有 venv 跑过 `uv pip sync -r requirements.txt`（或手动 `uv pip install -r`）。requirements.txt **刻意不含** torch/editable，sync 会拆掉它们。修复：`FRESH=1 ./setup_env.sh` 全新重建（旧环境自动备份为 `env_isaaclab_bak_*`）。以后全量同步请用 `requirements-full.txt` |
| `CUDA initialization failure` / `no CUDA-capable device` | GPU 没通 → 第 3 节 |
| `ModuleNotFoundError: scripts` | 没用 `run_train.sh`，缺 PYTHONPATH → 第 1 节末尾 |
| `RuntimeError: CUDA out of memory` | envs 太多 → `NUM_ENVS=512` |
| 卡在启动且日志不增长、nvidia-smi 无进程 | 内存耗尽在换页 → 降低 num_envs / 检查 swap |
| `terrain_out_of_bounds ... device` 之类报错 | 本仓库已修过 `terminations.py`，保持现状即可 |
| 启动 10 分钟没输出但 CPU 忙 | shader 编译中，正常 → 4.1 节 |
